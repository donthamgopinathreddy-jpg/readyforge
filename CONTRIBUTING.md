# Contributing to ReadyForge

ReadyForge rules should be evidence-based, reproducible and implementation-neutral.

A new rule must define:

- stable rule ID
- domain
- title
- why it matters
- severity
- automation level
- detection method
- expected evidence
- remediation guidance
- false-positive considerations
- acceptance criteria
- references where appropriate

Do not add rules that merely encode personal stylistic preferences.

Security rules should prefer OWASP MASVS, platform documentation and backend vendor documentation as primary references.
